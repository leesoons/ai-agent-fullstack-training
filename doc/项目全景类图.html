项目全景类图

一条线讲清「进程内集成」：agent-loop 直接吃 GatewayService，GatewayController 只是对外的 HTTP 入口。

应用层 编排层 执行内核 网关 MCP 接口 ◁ 实现 ⇢ 依赖/调用
总纲：编排层只依赖两个抽象——ModelClient（「调模型」）和 ToolRuntime（「执行工具」）。具体供应商和具体工具都是抽象背后可替换的实现。
ModelClient 与 GatewayController 的关系（你问的点）：它俩没有直接关系。GatewayModelClient 实现 ModelClient 后，是进程内直接注入 GatewayService 调 gateway.chat()，不经过 Controller。GatewayController 只是把同一套 GatewayService 暴露成 HTTP（/v1/chat 等）给外部客户端。两条路径在 GatewayService 汇聚，这是「进程内集成」与「HTTP 集成」的关键区别。
两条垂直主线：① 模型链 AgentLoop → ModelClient →（GatewayModelClient 实现，进程内）→ GatewayService → UpstreamClient → LlmAdapter；② 工具链 AgentLoop → ToolRuntime → ToolRegistry → ToolDefinition → ToolHandler。二者在 AgentLoop 汇合。
工具来源：ToolRegistry 里的 ToolDefinition 有两个来源——本地 SampleTools 插件、MCP 侧 McpHost 投影的远端工具；它们以同一种快照进入执行内核，内核不感知来源差异。
