项目整体演进图

一张会生长的图：现状架构为底，每节学的能力作为「叠加层」画上去，看清它到底动在哪里

现有能力 2-3 已接入的 MCP 2-4 已完成的治理叠加 2-5 已完成的基础设施 v2 需重点理解的边界

① 项目整体架构：模块分层与依赖方向（现状，含 2-5）

单向依赖，外部能力只能以「工具」身份进入核心域，不反向影响编排与执行。

② 调用主链：谁先谁后（现状）

AgentLoop 先问模型，模型只提议工具名与参数；真正执行永远经过 ToolRuntime。

③ 2-4 治理升级：叠加在 ToolRuntime 上（已完成）

原有 prepare / execute / finalize 三阶段不变，但每一段都被「治理能力」填满。

④ 2-5 基础设施 v2 叠加（已完成）

这一节不新建模块，而是把「超时 / 重试 / 审批 / 循环 / 命名」五件事收紧成可验证的闭环。

① 超时重试语义修复

ToolRuntime.executeWithRetry：超时只允许 Effect.READ 重试，写操作即使被标 idempotent 也不重放；新增 fallbackHandler 最后防线，其自身超时不再重试。

② LoopGuard 循环护栏

LoopGuard + LoopBudgetConfig：六维预算（轮数/工具数/重复/Token/费用/时长），beforeToolCall 前置拦截、shouldStop 循环熔断。2-5 收尾：AssistantTurn.Usage + observeAssistantUsage，Token/Cost 两维真实喂数（Cost 由网关计价回填）。

③ 可恢复审批状态机

ApprovalStatus：PENDING → APPROVED/REJECTED → EXECUTING → CONSUMED/FAILED；ApprovalStore 用 claim 抢锁（CAS）防重放、digest 绑定防篡改、TTL 过期。2-5 收尾：未获批准时签发 PENDING 并返回 AWAITING_APPROVAL，AgentLoop 熔断等人，人工批准后带 approvalId 恢复。

④ 命名投影与碰撞查重

NameProjection.toModelToolName 把内部名投影成合法模型名；ToolRegistry.register 对投影名显式查重，不同内部名投影撞名直接拒绝。

⑤ MCP Streamable HTTP 传输

McpTransport 接口 + StreamableHttpClientTransport（JDK HttpClient，JSON-RPC + SSE 解析 + Mcp-Session-Id）；McpServerConfig 把「连哪个 MCP」配置化，新增 Server 只加一条配置。

⑥ Live 验收入口

DeepSeekLive / LkCoffeeLive：缺 DEEPSEEK_V4_PRO_API_KEY / LUCKIN_MCP_TOKEN 时 fail()，禁止回退 Fake；类名以 Live 结尾，默认不随 mvn test 运行。

⑦ Trace 贯穿

TraceSink + TraceEvent：ToolRuntime 记 tool.execution_end，AgentLoop 记 loop.turn_end/final_answer/stop/awaiting_approval，按 traceId 聚合出一次 Run 的完整执行链。

⑧ 租户资源范围预检

SampleTools.verifyCustomerScope：租户→客户前缀映射，越权读取抛 RESOURCE_SCOPE_DENIED，让 ToolPrecheck 钩子有落地样例。

⑤ 演进路径（这张图会持续叠加）

2-1 / 2-2 · Function Calling + Tool Runtime
2-3 · MCP 外部工具来源（已完成）
2-4 · 工具治理与安全边界（已完成）
2-5 · 基础设施 v2：超时/审批/LoopGuard/命名投影（已完成）
阶段 3 · 整体 Agent 项目整合（已落地）
2-5 收尾 · Streamable HTTP / LoopGuard usage / live 验收（本次）
2-5 终收尾 · 审批挂起 / Trace / precheck / Cost 回填（本次）
为什么要做「会生长的图」：每一节都不是新建模块，而是把 tool-runtime-java / agent-core-java 里的既有类从「能跑」升级成「可治理、可验证」。2-5 是这条升级链的最后一环。
2-4 三个落地阶段：Stage 1 = Effect/ToolPolicy/PermissionEngine；Stage 2 = ApprovalStore/ToolPrecheck；Stage 3 = ResultProjector/AuditSink/写锁/invokeBatch。
2-5 新增与改动：新增 LoopGuard/LoopBudgetConfig/NameProjection/ApprovalStatus/McpTransport/StreamableHttpClientTransport/McpServerConfig/AwaitingApprovalException/TraceSink/TraceEvent；改动 ToolRuntime（超时+fallback+审批挂起）/ ApprovalStore（状态机+tryConsume）/ ToolRegistry（碰撞查重）/ ToolDefinition（fallback）/ AgentLoop（LoopGuard + usage + Trace + AWAITING 熔断）/ ModelClient（Usage）/ GatewayModelClient（提取 usage+cost）/ McpClient（依赖传输抽象）/ TokenUsage（costUsd）/ GatewayService（回填 cost）/ SampleTools（租户预检）。
测试基线：全量 mvn test 80 个测试全绿；另有 DeepSeekLive / LkCoffeeLive 两个 Live 验收（缺 key 必须失败），默认跳过。
一句话总纲：调用前门禁 → 调用中受控 → 调用后保护，循环级再加 LoopGuard。模型输出永远不可信，只有治理管线可信。
