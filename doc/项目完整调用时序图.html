项目完整调用时序图

一次工具调用的完整闭环：模型提议 → LoopGuard → ToolRuntime 治理 → Handler 执行 → 审计与结果保护 → 回填模型

实线 请求 虚线 返回 ◆ ToolRuntime 内部动作 粉色 2-4 治理能力 黄色 2-5 LoopGuard / 超时 / 审批

链路要点

① 三段式已落在代码方法名上：ToolRuntime.invoke 只做编排，内部调用 prepare、execute、finalizeSuccess / finalizeDenied，图和代码一一对应。
② 模型只提议，不执行：AgentLoop 收到 tool_calls 后先过 LoopGuard.beforeToolCall，再交给 ToolRuntime；任何门禁拒绝都在 Handler 被调用之前短路。
③ 超时与重试（2-5）：execute 里超时只允许 Effect.READ 重试，写操作绝不重放；可重试失败降级到 fallbackHandler，fallback 自身超时不再重试。
④ 审批可恢复（2-5）：需要确认的工具在 prepare 里经 ApprovalStore 核销；其内部是 PENDING → APPROVED → EXECUTING → CONSUMED/FAILED 状态机 + claim 抢锁，一次授权只执行一次。
⑤ 回模型的是安全视图：ToolResult.toModelMessage() 已脱敏、限规模并标记 untrusted:true，原始结果不会直接进入模型上下文。
⑥ LoopGuard 双观察点（2-5 收尾）：模型每轮返回后 AgentLoop 立即 observeAssistantUsage(totalTokens, costUsd) 累计 Token/费用；工具调用前 beforeToolCall 累计工具数/重复调用；每轮结束 observeTurn + shouldStop() 累计轮数/时长。三个观察点分别喂六维预算。
⑦ MCP 双传输（2-5 收尾）：Handler 的「经 MCP 闭包」路径由 McpClient 依赖 McpTransport，同一套握手/发现/调用同时支持 stdio 与 StreamableHttpClientTransport（JSON-RPC + SSE + Mcp-Session-Id）；新增 Server 只加一条 McpServerConfig。
⑧ Live 验收（2-5 收尾）：DeepSeekLive / LkCoffeeLive 缺 key 必须 fail()，禁止回退 Fake；默认不随 mvn test 运行。
⑨ 审批挂起分支（2-5 终收尾）：prepare 遇到 requiresApproval 且无有效审批时，签发 PENDING 审批单并返回 AWAITING_APPROVAL（非错误）；AgentLoop 检测到后调 shouldStop(pendingApprovalId) 熔断本轮，不把等待当错误回喂模型。人工 decide 后带 approvalId 重跑，tryConsume 核销并执行。
⑩ Trace 贯穿（2-5 终收尾）：ToolRuntime 每笔调用写 tool.execution_end，AgentLoop 每轮写 loop.turn_end、结束写 loop.final_answer/stop，全部进 TraceSink 按 traceId 聚合，形成一条完整执行链。
⑪ Cost 回填（2-5 终收尾）：网关 UsageService.calculateCost 按价目表算好 cost 后，GatewayService 回填进 TokenUsage.costUsd，GatewayModelClient 读出来喂给 LoopGuard，cost 维不再是 0。
